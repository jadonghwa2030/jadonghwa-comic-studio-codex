# 기능 스펙: Cinematic Mode (Show / 드라마처럼 “보여주기”)

## 배경
현재 앱은 “정밀한 분석 + 근거 기반 설명”에 최적화되어 있어, 사용자가 원하는 경우에도 만화가 **설명형(educational)**으로 흐르기 쉽습니다.

하지만 일부 질문은 **설명보다 ‘연출/몰입’이 목적**입니다.
- 예: “샘 알트먼과 데미스 하사비스가 UFC 선수가 되어 경기를 펼친다면?” → 분석/설명이 아니라 **경기 장면 자체**를 영화/드라마처럼 보여주고 싶음.

---

## 목표(Goals)
- 사용자가 `Learning(설명)`과 `Cinematic(연출)` 중 하나를 선택할 수 있다.
- `Cinematic`에서는 **분석/해설/정리** 대신, **행동·대사·표정·카메라·무드**로만 이야기가 전개된다.
- 기존 `Question Type(explain/compare)`와 독립적으로 동작한다. (조합 가능)

## 비목표(Non-goals)
- Cinematic이 “정답/근거/팩트”를 더 잘 맞추게 만드는 것
- 장르(스릴러/로맨스/액션 등)까지 완전한 장르 편집기를 제공하는 것 (추후 확장)
- 폭력/혐오/선정성 강화를 통한 자극적 연출

---

## UX: 어디서 선택하나?
권장 위치: **03. The Mission**
- 이유: 플래너(대사/컷 구성)의 출력 성격을 바꾸는 옵션이며, 이미 질문/독자/리서치/디테일 등을 모으는 단계이기 때문.

UI 제안(라디오/토글):
- Comic Mode: `Learning` / `Cinematic`
- Cinematic 선택 시 안내 문구:
  - “설명/해설 없이 장면으로만 전개합니다.”

---

## 데이터 모델
새 타입:
- `ComicMode = "learning" | "cinematic"`

설계 원칙:
- `QuestionType(explain/compare)`는 질문 구조, `ComicMode`는 **연출/출력 방식**
- `NarrativeRole(narrator/actor)`와는 별개이지만, Cinematic에서는 `actor`가 더 자연스럽기 때문에 UI에서 “추천” 정도로만 유도(강제 X)

---

## Planner 프롬프트(핵심)

### Learning(기존)
- Deep-Dive Framework 유지
- 오해 교정/정의/근거/비유 등 설명 구조 중심

### Cinematic(신규)
핵심 규칙:
- **설명/분석/정리/교훈** 금지 (대사에서 특히 금지)
- 컷 구성은 “연출 비트”로 강제(예: 도입 → 긴장 상승 → 전환/반전 → 클라이맥스/훅)
- `scene`: 장소/상황/서라운드(관중, 조명, 소리 등) 묘사
- `acting`: 표정/몸짓/리듬(호흡, 스텝, 시선, 손동작) 등 구체 지시 필수
- `dialogues`: 짧고 현실적인 대사(화자 이름/나레이션 표기 금지)
- `camera/mood`: 액션/드라마 톤에 맞게 적극 활용

실존 인물/what-if 처리:
- “사실 주장”처럼 단정하지 말고 **가상의 ‘한 편의 장면’**으로 작성
- 과도한 비방/모욕/명예훼손성 설정 금지

폭력 묘사 제한:
- UFC/격투 묘사는 가능하되, **유혈/절단/고어** 등 잔혹 표현은 금지(액션은 PG-13 정도로)

---

## 리서치 모드와의 관계
- Cinematic은 원칙적으로 “팩트 기반 설명”이 목적이 아니므로, `user research`를 필수로 강제하지 않는 편이 UX에 유리할 수 있음(추후 개선 후보).
- 단, 현재 MVP에서는 기존 흐름을 유지하되:
  - user research가 들어오면 “팩트 주장”을 줄이고 **세계관/디테일 재료**로만 사용하도록 지시

---

## MVP 구현 범위(최소)
1) `ComicMode` 타입 추가 및 UI(03 단계)에서 선택
2) 플래너 입력 파라미터에 `comic_mode` 전달
3) `services/planner.ts`에서 `systemInstruction/prompt`를 `comic_mode`로 분기

---

## 추후 확장 아이디어
- 장르 프리셋(액션/법정/스릴러/로맨스/스포츠 중계톤 등)
- Cinematic 전용 “승부/결말” 제어(승/패/무승부/오픈엔딩)
- Cinematic에서 Research Mode 기본값을 `auto_gemini` 혹은 “no research”로 바꾸는 UX
- Cinematic에서 페이지 수 자동 추천(2~4p 중심)
